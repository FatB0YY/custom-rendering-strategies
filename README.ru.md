# Custom Rendering Strategies

Написанные вручную реализации основных стратегий рендеринга и их оптимизаций — без Next.js, Remix и любого другого фреймворка, который скрывает механику.

Смысл в том, чтобы увидеть, что эти фреймворки делают на самом деле. `getStaticProps`, `revalidate` и потоковый SSR — не магия: это шаг сборки, который пишет HTML-файлы, проверка временной метки, запускающая регенерацию, и ответ, который сервер держит открытым, отдавая чанки. В каждой папке одна из этих вещей реализована с нуля.

## Сравнение стратегий

| Стратегия | Когда генерируется HTML | TTFB | Свежесть данных | Где применять |
| --- | --- | --- | --- | --- |
| CSR | В браузере, после загрузки JS | Быстрый (пустая оболочка) | Всегда актуальные | Дашборды, админки, всё за авторизацией |
| App Shell | Оболочка из кеша, содержимое в браузере | Очень быстрый | Всегда актуальные | Повторные визиты, PWA-подобные приложения |
| SSG | На этапе сборки | Самый быстрый | Устаревают до пересборки | Документация, промо-страницы, блоги |
| Partial SSG | Популярные страницы при сборке, остальные по запросу | Смешанный | Смешанная | Большие каталоги с горячим подмножеством |
| ISR | При сборке, затем фоновая регенерация | Самый быстрый | Отстают не более чем на окно ревалидации | Каталоги, которые меняются, но не на каждый запрос |
| SSR | На каждый запрос, на сервере | Медленнее — ждёт данные | Всегда актуальные | Персонализированные страницы, которым нужна индексация |
| SSR streaming | На каждый запрос, чанками | Быстрый — сначала оболочка | Всегда актуальные | Страницы, где часть данных медленная |
| SSI | Фрагменты собираются сервером или CDN | Быстрый | Отдельная по фрагментам | Общие шапки, подвалы, виджеты на разных страницах |

## Реализации

### `react-csr`

Клиентский рендеринг. Сервер отдаёт почти пустой документ, всю страницу строит React в браузере. Базовая точка отсчёта для всех остальных стратегий — и причина, по которой они существуют: до загрузки и выполнения бандла не видно ничего.

### `react-csr-app-shell`

CSR с подходом App Shell. Статический каркас — layout, навигация, плейсхолдеры — отдаётся и отрисовывается сразу, а зависящие от данных части приходят следом. Пользователь видит структуру вместо белого экрана: меняется воспринимаемая скорость, хотя реальные тайминги данных те же.

### `custom-ssg`

Полная генерация статики. Страницы рендерятся в HTML во время сборки, серверу остаётся только отдавать файлы. Быстрее не бывает — и устаревают данные тоже сильнее всего: изменение требует пересборки.

### `custom-partial-ssg`

Частичная генерация статики. На этапе сборки пререндерится только часть страниц, остальные создаются по запросу. Ответ на ситуацию с каталогом, где пререндер всех страниц сделал бы сборку неприемлемо долгой, но небольшое подмножество даёт основной трафик.

### `custom-isr`

Инкрементальная регенерация статики. Страницы отдаются как статика, но по истечении окна ревалидации следующий запрос запускает фоновую регенерацию, пока продолжает отдаваться устаревшая версия. Компромисс между скоростью SSG и свежестью SSR — и самая неочевидная в реализации стратегия из всего набора.

### `custom-ssr`

Классический серверный рендеринг. HTML генерируется на каждый запрос, поэтому ответ содержит реальный контент — индексируемый и сразу видимый. Цена — TTFB: прежде чем что-то отправить, сервер должен получить данные.

### `custom-ssr-slow-request`

Намеренно замедленный SSR-запрос. Нужен, чтобы сделать эту цену наглядной: при медленном источнике данных ждёт вся страница, и пользователь не видит вообще ничего. Именно эту проблему решает следующая реализация.

### `custom-ssr-stream`

Потоковый серверный рендеринг. Сервер отправляет оболочку, как только она готова, и досылает остальное по мере получения данных, вместо того чтобы держать ответ до полной готовности. TTFB возвращается к почти статическим значениям, а контент остаётся серверным.

### `custom-ssi`

Server Side Includes. Сервер или CDN собирает страницу из отдельно закешированных фрагментов. Позволяет закешировать общую шапку, подвал или виджет один раз и переиспользовать на страницах с разными правилами кеширования.

### `stream`

Демонстрации стриминга данных — транспортный механизм, лежащий в основе потокового SSR.

## Запуск

Каждая папка — самостоятельный проект. Перейдите в нужную и запустите:

    cd custom-ssr
    npm install
    npm run dev
